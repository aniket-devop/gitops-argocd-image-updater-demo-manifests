This is the **GitOps configuration repository** for the [`gitops-argocd-image-updater-demo`](https://github.com/aniket-devop/gitops-argocd-image-updater-demo) project. It holds **only** the Kubernetes manifests that describe the desired state of the application — no application code lives here.

This repo is the **single source of truth** watched by Argo CD. Nothing in the cluster changes unless it's first committed here — either by a human, or automatically by Argo CD Image Updater.

---

## 📌 Role in the Pipeline

```
GitHub (app repo) → GitHub Actions → GHCR → Argo CD Image Updater → this repo → Argo CD → Kubernetes
```

1. The application repo's CI builds and pushes a new image to GHCR
2. **Argo CD Image Updater** detects the new tag and writes the updated image reference **into this repo** via a Git commit
3. **Argo CD** watches this repo and automatically syncs the Kubernetes cluster to match

No one runs `kubectl apply` by hand — this repository's contents *are* the deployed state.

## 📂 Structure

```
k8s/
├── kustomization.yaml    # Kustomize base — lists the resources below
├── deployment.yaml       # Deployment spec (replicas, probes, container image)
├── service.yaml          # ClusterIP Service exposing the app on port 80
└── .argocd-source-*.yaml # Auto-generated by Argo CD Image Updater — current image override
```

| File | Purpose |
|---|---|
| `kustomization.yaml` | Kustomize entry point; declares which manifests belong to this app |
| `deployment.yaml` | Runs 2 replicas of the app, with liveness/readiness probes on `/health` |
| `service.yaml` | `ClusterIP` Service routing port `80` → container port `5000` |
| `.argocd-source-gitops-argocd-image-updater-demo.yaml` | **Auto-managed file.** Written by Argo CD Image Updater on every detected image update — do not edit by hand |

---

## 🤖 How the Auto-Commit Works

Argo CD Image Updater is configured (in the Argo CD `Application` resource) to:
- Watch `ghcr.io/aniket-devop/gitops-argocd-image-updater-demo` for new tags using a `semver` strategy
- On finding a newer tag, write the image override into `.argocd-source-gitops-argocd-image-updater-demo.yaml` in **this** repository
- Commit and push that change using a GitHub PAT scoped to `Contents: Read and write` on this repository only

Argo CD then picks up the commit and reconciles the cluster — typically within its polling interval, with no manual intervention.

## ☸️ Applying Manually (for local testing)

```bash
git clone https://github.com/aniket-devop/gitops-argocd-image-updater-demo-manifests.git
cd gitops-argocd-image-updater-demo-manifests
kubectl apply -k k8s/
kubectl get pods
```

> In the actual GitOps flow, this step is never run manually — Argo CD applies these manifests automatically.
